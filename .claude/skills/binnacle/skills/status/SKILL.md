1. Call the `binnacle` MCP server's `project_status` tool once, with no arguments. If this session has no `binnacle` MCP tools, run each Binnacle tool this skill calls as `binn call <tool> '<arguments as one JSON object>'` in the shell instead, with the same arguments, and read the JSON it prints: what the tool returns, or the same error with its code. If it fails, stop. Say what failed, worded from the error's code, message and `params`, and give the human the fix without running it yourself:

   - If the shell cannot find `binn` (`command not found`, exit 127), `binn` is not on this harness's PATH (see the README's setup section).

   Binnacle is optional. Until it answers, `git status` and the manifest at `.binnacle/project.yaml` give the Git and tracker facts.

If `git.available` is false, give its reason in words instead of the Git facts.
   - **What is wrong**, only when something is: each diagnostic, worded, such as a remote that does not match the manifest.
