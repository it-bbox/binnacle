Binnacle

One project memory. Any coding agent.

Binnacle is a local, provider-agnostic AI Engineering Control Plane: persistent project context, workflow and observability across Claude Code, Codex, Gemini, GLM and other coding agents. It keeps project state outside chat sessions, hands fresh agents a compact and current context, collects spend telemetry, and leaves the human in charge of the process.

Install

npm i -g @it-bbox/binnacle
binn daemon start

What Binnacle's own work cost

Binnacle was built with the coding agents it is built for, and it recorded the token usage of the sessions that did the work. This write-up reads those records back: what the work cost and where the tokens went.

It is all summary aggregates. No ticket, task or session is named, and every figure is Binnacle's own reading of its usage data on 31 October 2026.

How to read the numbers

  • A record is one call, counted once. When a harness's session file and its OpenTelemetry export both report the same call, Binnacle stores one record for it.
  • Token kinds are never added together. Cached input is context the provider re-read from its cache; reasoning is the part of the output the model thought in. They are shown side by side, as Binnacle shows them.
  • A partial counter is a floor. Some harnesses report only some token kinds. Binnacle reports the missing ones as no data, never as zero, so a total over a partial counter is a lower bound.
  • Calculated readings are marked. Every sum, mean and share below is Binnacle's calculation over the stored records; the token counts themselves are what each harness reported.

What a completed Task cost

  • 200 completed Tasks have attributed runs; 50 more were completed without a run Binnacle could attribute to them.
  • Mean per completed Task, calculated over those 200: 79.6 records, 2,587 input, 11,934,411 cached input, 261,980 cache creation, 54,354 output and 17,861 reasoning tokens.
  • Mean runs per Task, calculated: 4.2, of which 3.3 were subagent runs.
  • Rework share, calculated: 30.5% — rework tokens over implementation plus rework tokens, averaged over completed Tasks.
  • First-pass acceptance, calculated: 8.0% — the share of reviewed completed Tasks that needed no rework at all.

The method

Everything here is read from Binnacle's own usage store on 31 October 2026. The totals, the breakdown by role, the weekly totals and the derived readings match usage_get on that date; the breakdown by model is read from the same stored records, counted the same way, because usage_get does not group by model. The figures are one reading, taken at one moment; Binnacle keeps recording as it works, so a later call sees a few more records. Binnacle stores tokens, never cost or price. A calculated reading is marked so, and a reporting gap is said as no data, never as zero.

Сколько стоила работа над самим Binnacle

Binnacle создавался теми же агентами, для которых он и сделан, и записывал расход токенов в сессиях, где шла работа. Этот текст читает эти записи обратно: сколько стоила работа и куда ушли токены.

Здесь только сводные агрегаты. Ни один тикет, задача или сессия не назван, а каждая цифра — то, как сам Binnacle прочитал свои данные об использовании на 31 октября 2026 года.

Как читать цифры

  • Запись — это один вызов, учтённый один раз. Когда файл сессии harness и его экспорт OpenTelemetry сообщают об одном и том же вызове, Binnacle хранит одну запись о нём.
  • Виды токенов никогда не складываются. Входные из кэша — это контекст, который провайдер перечитал из своего кэша; рассуждения — часть выходных, в которой модель думала. Они показаны рядом, как их показывает Binnacle.
  • Неполный счётчик — не полный итог. Некоторые harness сообщают только часть видов токенов. Отсутствующие Binnacle называет «нет данных», никогда не нулём, поэтому сумма по такому счётчику — нижняя граница.
  • Расчётные чтения помечены. Каждая сумма, среднее и доля ниже — расчёт Binnacle по сохранённым записям; сами счётчики токенов — то, что сообщил каждый harness.

Куда ушли токены, по ролям

Binnacle относит каждый запуск к роли, которую тот играл: продуктовая работа над роадмапом и спецификациями, реализация в ветке тикета, ревью силами субагента, доработка после ревью и «роль неизвестна» для работы, которую он не может отнести. Роль — расчётное чтение по ветке и коммитам запуска.

Сколько стоила одна завершённая задача

  • 200 завершённых задач имеют отнесённые к ним запуски; ещё 50 завершены без запуска, который Binnacle мог бы к ним отнести.
  • В среднем на завершённую задачу, расчёт по этим 200: 79,6 записи, 2 587 входных, 11 934 411 входных из кэша, 261 980 записей в кэш, 54 354 выходных токена и 17 861 токен рассуждений.
  • В среднем запусков на задачу, расчёт: 4,2, из них 3,3 — запуски субагентов.
  • Доля доработки, расчёт: 30,5% — токены доработки, делённые на токены реализации и доработки вместе, в среднем по завершённым задачам.
  • Приёмка с первого прохода, расчёт: 8,0% — доля прошедших ревью завершённых задач, которым доработка не понадобилась вовсе.

Метод

Всё здесь прочитано из собственного хранилища Binnacle 31 октября 2026 года. Итоги, разбивка по ролям, недельные итоги и расчётные чтения совпадают с usage_get на эту дату; разбивка по моделям прочитана из тех же сохранённых записей и посчитана так же, потому что usage_get по моделям не группирует. Цифры — одно чтение, снятое в один момент; Binnacle продолжает записывать, пока работает, поэтому более поздний вызов увидит ещё несколько записей. Binnacle хранит токены, но никогда — стоимость или цену. Расчётное чтение помечено, а пробел в отчётности назван «нет данных», никогда не нулём.
