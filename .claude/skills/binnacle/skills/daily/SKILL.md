---
name: daily
description: Show what changed in this project since the previous daily on this machine, then what waits for the owner, what is broken and what can start next, in three to six lines, giving the rest when asked. Records the next daily's baseline and changes nothing else.
argument-hint: "[commit to look back from]"
disable-model-invocation: true
---

Give the human each command you offer them alone in a fenced block, which copies in one click: a skill such as `/binnacle:daemon start` in a plain fence, a shell command such as `binn daemon start` in a `bash` fence.

Speak to the person in the language of this conversation; these instructions stay English. Word every attention item, diagnostic and error from its `code`, `message` and `params`, in that language, with the Task ids, paths and numbers it names, and never show its code: codes are for you. Keep commands, paths, Task ids, branch names, model names, a file's own markers such as `Status: DONE`, and the names Binnacle, Graphify, Obsidian, Serena and the harnesses as written. Mark a value Binnacle calculated with one word in brackets, "(estimate)", and a reading from runs with "(from activity)"; say an unknown value as "no data", never zero. In Russian, the marks are "(оценка)", "(по активности)" and "нет данных", and the terms are: Task — задача; Epic — эпик; Current Epic — текущий эпик; Next action — следующий шаг; Suggested step — предложенный шаг; Product Snapshot — снимок проекта; Product session — продуктовая сессия; Product Steward — продуктовый агент; roadmap — роадмап; Spec — спецификация; Ticket — тикет; Epic brief — бриф эпика; Task brief — бриф задачи; Vision — видение; Backlog — бэклог; Ready — готова к старту; In progress — в работе; BLOCKED — заблокирована; Review — ревью; Done — готово; Unmet dependency — невыполненная зависимость; Question — вопрос; Answer — ответ; Waiting for the owner — ждёт владельца; Conflict risk — риск конфликта; Parallel limit — лимит параллельной работы; Checkout — рабочая копия; Harness — клиент агента; Provider — провайдер; AgentRun — запуск; Review run — запуск ревью; Rework run — доработка; Unassigned — без задачи; Roles — роли (разработчик, ревьюер, архитектор, тестировщик, безопасность, DevOps, аналитик); CI state — состояние CI; Audit — аудит; Finding — находка; Migration plan — план перехода; Stranded document — бесхозный документ; Checkpoint — чекпойнт; Autopilot — автопилот; Autostart — автозапуск; Mod — мод; Vault projection — проекция в Obsidian; Context pressure — заполненность контекста; Session artifact — файл сессии; Harness support level — уровень поддержки; Project registry — реестр проектов; Project Brain — знания проекта. The roadmap's statuses read не начат, спецификация, тикеты, в работе, готов; a Task's states read бэклог (`BACKLOG`), готова (`READY`), в работе (`ACTIVE`), заблокирована (`BLOCKED`), на ревью (`READY_FOR_REVIEW`), одобрена (`APPROVED`), готова к слиянию (`MERGE_READY`), слита (`MERGED`), готово (`DONE`), отменена (`CANCELLED`); CI reads проходит (`passing`), падает (`failing`), идёт (`running`), нет проверок (`none`); a finding reads в порядке (`ok`), пробел (`gap`), неизвестно (`unknown`). Git's words take their usual Russian, ветка and коммит; `worktree` stays.

1. Call the `binnacle` MCP server's `project_detect` tool. If this session has no `binnacle` MCP tools, run each Binnacle tool this skill calls as `binn call <tool> '<arguments as one JSON object>'` in the shell instead, with the same arguments, and read the JSON it prints: what the tool returns, or the same error with its code. If it fails, stop. Say what failed, worded from the error's code, message and `params`, and give the human the fix without running it yourself:
   - `daemon.unreachable`: `/binnacle:daemon start`, or `binn daemon start` at a terminal.
   - `project.not_registered`: `/binnacle:register`, or `binn project register` run in the main checkout.
   - If the shell cannot find `binn` (`command not found`, exit 127), `binn` is not on this harness's PATH (see the README's setup section).

   Binnacle is optional. Until it answers, the project's position is in its roadmap and in its tickets' `Status:` lines.
2. Call `daily_get` once.
   - With no argument, call it with no arguments. It returns the delta since the last daily or checkpoint and records this HEAD as the next baseline. That is what running `/binnacle:daily` asks for. Do not call it a second time to check: the second call returns an empty delta and records again.
   - If the human passed a commit (`$ARGUMENTS`), pass it as `since`. The delta then runs from that commit and records nothing.
   - `request.invalid` means that commit does not exist or is not an ancestor of HEAD. Say so, and suggest another commit.
3. **Open with three to six lines**, in this order, and leave out a line with nothing in it:
   - **What changed**, in one line: the range in words, since the last daily, the last checkpoint or the commit passed (`from.source`), or, when `fallback` is set, its message in words, since the range was chosen by the fallback and not by a baseline; the number of commits; and what moved, each counted: Task transitions, new tickets, roadmap status changes and decisions. When `dirty` is true, add that uncommitted edits are not in it. A list that is null or marked `available: false` is "no data", never zero, and "nothing changed since `<from.commit>`" is said only when every list is known and empty.
   - **What waits for the owner**, from `pendingDecisions`, as of now: the unanswered questions, the approvals (Tasks in `READY_FOR_REVIEW`) and the Tasks for the owner to start (triaged `ready-for-human`), each counted, with the first of each by Task id and title. When the section or a list is marked `available: false`, give its reason in words.
   - **What is broken**: a failing default branch from `ci`, then the attention items other than `ci.failing`, worded.
   - **What can start next**: the first of `readyToStart` by id and title, how many others, and its start command, `/binnacle:task run <its ticket>`, alone in a fenced block.

   Then one line on what else you can show: the commits, what moved with each ticket or ADR, every question, approval and Task ready to start, and CI by pull request. Do not run that command until the person asks.
4. **When the person asks for more**, give it from the same answer, without calling again, leaving out a list that is empty:
   - **Range**: from `from.commit` (`from.source`) to `head`. A null `from.commit` means the range starts at the first commit.
   - **Commits**: the count, then the subjects, with "and N more" for any remainder.
   - **Task transitions** (`from` → `to`), **new tickets**, **roadmap status changes** and **decisions**, each with its ticket or ADR path. A null list means its source could not be read, and the attention items say why. A list with `available: false` could not be computed, as on a remote tracker's first daily or with a commit passed: give its `reason` instead, so that it is not read as nothing changed.
   - **Waiting for the owner**: the unanswered **questions**, each with its Task id, title, ticket path, its text and the branch it was read from when `branch` is set; the **approvals**, waiting for the human's review; and the human's **to start**, each with id, title and ticket path. Give every remainder as "and N more".
   - **CI**, from `ci`, as of now and as the forge reports it, never Binnacle's reading: the forge, `forge.provider` and `forge.repository`; the default branch's state, with its commit and link; then each open pull or merge request with its number, title, branch, the Task it maps to (`taskId`) or no Task, whether it is a draft, and its state, with "and N more" for the remainder. When `ci` is marked `available: false`, give its `reason`.
   - **Attention**: every item, worded.
   - **Can start next**: every `readyToStart` Task, with id, title and ticket path.

Change nothing else: no files, no commits, and no Binnacle calls other than the two above.
