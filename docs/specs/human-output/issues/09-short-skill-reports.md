# 09: The skills' short reports

Status: READY
Triage: ready-for-agent
Blocked by: None
Spec: `docs/specs/human-output/spec.md`

**What to build:** each reporting skill opens with three to six lines in the person's language (spec, *Short first*, *The skills' short report*). `/binnacle:product`, `/binnacle:daily`, `/binnacle:status`, `/binnacle:task` without `run`, and `/binnacle:audit` follow the spec's order, skill by skill; leave out a section with nothing in it; give the next command alone in a fenced block; end with one line on what else they can show; and give the rest when the person asks. Their instructions stay English and list the spec's Russian terms for the model. No attention code in a person's text: an item is worded from its code, message and `params`. A calculated value takes its one-word mark, an unknown "no data". `docs/03-mcp-and-skills.md` describes the short report.

- [ ] Each of the five skills names its opening lines in the spec's order and leaves empty sections out.
- [ ] None asks the model to show an attention code; each lists the Russian terms.
- [ ] The skills copy for other harnesses is regenerated by the build, and the existing package tests pass.
- [ ] Checked in review, and in the exit demonstration in a Russian chat.

## Comments

### Decisions

- **Each of the five skills carries the same *Words* paragraph**, after its fenced-block rule: speak the conversation's language, word every item from its `code`, `message` and `params` and never show the code, keep commands, paths, ids and names as written, the three marks, and `CONTEXT.md`'s *Russian words* with the states, CI and finding words. A skill is read alone by its harness, so the list is copied rather than referenced; a test in `apps/cli/test/pack.test.ts` reads `CONTEXT.md`'s table and fails when a skill drops or rewords a term.
- **The short report is step 3, the rest step 4**, given from the same answer without calling again. `/binnacle:status` has no rest: it answers in two or three lines and ends with `/binnacle:product` for the roadmap, the Tasks and usage.
- **`/binnacle:daily`'s next command is `/binnacle:task run <its ticket>`**, built from the first `readyToStart` Task's ticket, since the daily's sections carry no `start`; the start command is Binnacle's own under any workflow (ADR-0042).
- **`/binnacle:task`'s epic is its spec's folder**: `task_get` names no epic.
- **Three existing assertions in `pack.test.ts` pinned what the ticket changes**: the graph's `null` `behind` as "not known" (now "no data"), the conflict risk's "say so once" (now the "(estimate)" mark), and `/binnacle:status`'s "every item with its code". They follow the new text; every other assertion holds unchanged.
