# Запуск нового проекта

_English version: [01-new-project.md](01-new-project.md). Этот файл — русский дубликат; обновляется вместе с `01-new-project.md`._

## Быстрый путь

1. `git init` — создать репозиторий.
2. `binn init` — один план всего, что он настраивает, с одним подтверждением.
3. `/binnacle:roadmap` — видение и эпики.
4. `/binnacle:product` — первая Product-сессия.

Дальше каждый эпик идёт `/grill-with-docs` → `/to-spec` → `/to-tickets`, а каждый тикет — `/binnacle:task run <ticket>`, в отдельной сессии. В harness, отличном от Claude Code, каждый `/binnacle:<action>` называется `binnacle-<action>`: см. [Работу из другого harness](06-other-harnesses.ru.md#навыки-binnacle-в-другом-harness).

## 1. Создать репозиторий

Выполните `git init`. Если проект будет жить на GitHub или GitLab, сразу добавьте remote: `binn init` берёт из него tracker. Без remote tracker локальный, а тикеты — это Markdown-файлы в `docs/specs/`.

## 2. Настроить через `binn init`

Запустите `binn init` в репозитории. Он сначала всё продумывает, показывает это одним планом и спрашивает один раз: Enter или `y` записывает план, любой другой ответ не записывает ничего (ADR-0034). Он никогда не перезаписывает файл, дополняет файл только разделом, показанным в плане, и никогда не коммитит. Просмотрите и закоммитьте записанное сами. Как и весь `binn`, он говорит на языке вашей локали, по-русски или по-английски; `--plan --json` остаётся английским, поэтому план, показанный в одной локали, применяется из другой.

До плана он задаёт не больше трёх вопросов:

- **Окно импорта.** Он показывает, сколько сессий Claude Code и Codex нашёл в этом репозитории и дату самой старой. Затем спрашивает, сколько этой истории импортирует демон: по умолчанию 90 дней, другое число дней или `all`. `--window <days|all>` отвечает на вопрос заранее.
- **Язык документации.** Он предлагает язык, на котором написана документация репозитория, `en` или `ru`: язык корневого `README.md`, русский, если кириллических букв вне кода больше, чем латинских, а без README — язык вашей локали (`LC_ALL`, затем `LANG`). Enter принимает предложение. Ответ записывается в манифест как `knowledge.language`; манифест без него читается как английский. `--language <en|ru>` отвечает на вопрос заранее.
- **Автозапуск.** Там, где он доступен и ещё не включён, init спрашивает, запускать ли демон при входе в систему. «Да» делает `binn daemon autostart on` последним пунктом плана. `--autostart <yes|no>` отвечает на вопрос заранее.

Для нового репозитория план содержит:

- `.binnacle/project.yaml`, манифест: tracker, документы, найденные или устанавливаемые инструменты, окно импорта и язык документации;
- `docs/specs/` для локальных тикетов и заготовку `docs/roadmap.md`, чьё Next action — `/binnacle:roadmap`;
- соглашения планирования в `docs/agents/` и блок *Agent skills* в `AGENTS.md`, который на них ссылается;
- MCP-сервер `binnacle` в проектном файле каждого найденного harness, например `.mcp.json` для Claude Code;
- вне репозитория: плагин `binnacle` и навыки Binnacle, инструменты workflow и их MCP-серверы, экспорт OpenTelemetry, хранилище Obsidian и регистрацию проекта в запущенном демоне.

Роадмап, соглашения планирования и новый `AGENTS.md` пишутся на языке документации. В русском тексте слова, которые читает Binnacle, остаются английскими: заголовок таблицы роадмапа и его статусы, `## Current focus`, `Next action:`, поля и состояния заголовка тикета, метки триажа, `## Ticket header` и `## Agent skills`. Блок *Agent skills* тогда ещё и говорит, что документация ведётся на русском, чтобы любой агент писал на нём спецификации и тикеты.

Каждый пункт подробно: [Существующий проект](02-existing-project-adopt.ru.md#план-пункт-за-пунктом), *План, пункт за пунктом*. После плана tracker на GitHub или GitLab читается один раз, и init говорит, удалось ли его прочитать, а если нет — как дать ему токен только на чтение. Затем итог (Summary) начинается с команды, которую нужно запустить дальше, например `/binnacle:product`, или `binn daemon start` и `binn project register`, если демон не был запущен, и перечисляет, что создано, дополнено, запущено, не удалось или пропущено.

### Инструменты workflow

План устанавливает недостающее из набора Standard, вне репозитория. Инструмент, который уже есть в `PATH` или в списке Claude Code, или объявленный `false` в `capabilities` манифеста, не трогается. Наборы навыков ставятся в другие harness через CLI `skills` заново при каждом запуске, чтобы их получил и harness, установленный с тех пор. Скрипты-установщики не запускаются никогда: только менеджеры пакетов и собственные CLI harness.

| Инструмент | Как его ставит `binn init` | Его MCP-сервер |
| --- | --- | --- |
| Matt Pocock Skills | CLI плагинов Claude Code; CLI `skills` для других harness | — |
| Ponytail | CLI плагинов Claude Code; CLI `skills` для других harness | — |
| Serena | `uv tool install` | регистрируется в каждом найденном harness |
| Graphify | `uv tool install`, затем строится первый граф | регистрируется только для этого проекта |
| Context7 | ставить нечего | регистрируется в каждом найденном harness |
| ast-grep | npm | — |
| Obsidian | не ставится: init задаёт хранилище, если Obsidian перечисляет ровно одно | — |

Без `uv` init называет команду, которая его ставит, и оставляет Serena и Graphify вне плана. Без npm он так же оставляет вне плана Context7 и ast-grep.

### Из чата

В Claude Code `/binnacle:init [path]` делает то же самое из чата:

1. Он запускает `binn init --plan --json`. Там, где автозапуск доступен и ещё не включён, навык сначала спрашивает, запускать ли демон при входе в систему, и передаёт ваш ответ в init как `--autostart`. Если манифест ещё не называет язык, навык показывает язык документации, который предлагает init, и откуда взято предложение, спрашивает вас и передаёт ответ как `--language`. Затем он показывает весь план, каждый пункт целиком, вместе с историей сессий и окном импорта. Назовите другое окно, harness, куда не ставить навыки Binnacle, другой ответ об автозапуске или другой язык, чтобы увидеть план с ними.
2. Записывает план только ваше «да» в чате, через `binn init --apply <id>`. Если план изменился с момента показа, ничего не записывается и код выхода 3, а навык показывает новый план и спрашивает снова (ADR-0037).
3. Он показывает, что напечатал init, включая итог.

Навыку не нужен демон, и он никогда не коммитит. При остановленном демоне регистрация в план не входит: её добавляют `/binnacle:daemon start`, затем `/binnacle:register`. «Да» на вопрос об автозапуске делает `binn daemon autostart on` последним пунктом плана; при «нет» ничего не ставится, а итог называет эту команду на потом.

Когда init записывает `.mcp.json`, откройте новую сессию в репозитории и одобрите сервер `binnacle` проекта: Claude Code читает `.mcp.json` только при старте сессии. Сам навык приходит с плагином `binnacle`, который ставит на уровне пользователя первый `binn init` на машине, поэтому этот первый запуск делайте в терминале.

## 3. От видения к roadmap

Запустите `/binnacle:roadmap`. Демон ему не нужен, но нужны манифест и roadmap, которые пишет `binn init`; без них он останавливается.

1. Он читает `<knowledge.docs>/vision.md`. Если его нет, спрашивает, что это за проект, для кого он и что в него не входит, по одному вопросу, и по вашему «да» записывает видение вашими словами.
2. Он предлагает эпики в порядке зависимостей, сначала фундамент, у каждого — строка объёма. До «да» эпики можно менять, убирать, объединять и добавлять.
3. По вашему «да» он записывает строки roadmap, его раздел `## Epics` и Next action, которое грилит первый эпик. Он коммитит только эти файлы и никогда не пушит.

Этот вход для нового проекта он выбирает, когда в истории нет коммитов, кроме тех, что добавили файлы `binn init`, и Git не отслеживает исходного кода; `/binnacle:roadmap new` выбирает его в любом случае. При повторном запуске он предлагает дополнения и перестановки среди не начатых эпиков, никогда не меняет эпик `done` и никогда не удаляет строку со ссылкой на спеку. Кроме того, каждую пока не запланированную запись `<knowledge.docs>/product-inbox.md` он предлагает новым эпиком или частью не начатого либо называет оставленной в стороне, а по вашему «да» помечает каждую взятую запись «Planned as epic N» или «Planned into epic N» и оставляет её в этом файле.

## 4. Первая Product-сессия

Откройте свежий чат и запустите `/binnacle:product`, затем `/binnacle:daily`. Next action, записанное навыком roadmap, грилит первый эпик.

## 5. Каждый эпик, затем каждый тикет

Каждый эпик из roadmap идёт по потоку проектирования, начиная с Next action:

1. `/grill-with-docs` — обсудить эпик; грилинг заканчивается его brief.
2. `/to-spec` — оформить его спекой в `docs/specs/<slug>/`.
3. `/to-tickets` — нарезать спеку на тикеты.

Эти три навыка — из Matt Pocock Skills, и они читают соглашения, которые записал `binn init`, поэтому никакой навык настройки перед ними не запускается. Сам `binn init` их никогда не запускает. Затем каждый тикет выполняется в отдельной сессии командой `/binnacle:task run <ticket>`.
