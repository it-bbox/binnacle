# Запуск нового проекта

_English version: [01-new-project.md](01-new-project.md). Этот файл — русский дубликат; обновляется вместе с `01-new-project.md`._

## Путь пользователя

Быстрый путь, как его даёт README:

```text
git init
    ↓
binn init
    ↓
/binnacle:roadmap
    ↓
/binnacle:product
```

### 1. Создать репозиторий

Выполните `git init` и, где это уместно, выберите remote на GitHub/GitLab.

### 2. Инициализировать Binnacle

Целевая команда:

```bash
binn init
```

Что она должна делать:

- создать `.binnacle/project.yaml`;
- определить Git remote/tracker;
- зарегистрировать проект локально;
- установить/настроить MCP/клиентскую интеграцию Binnacle;
- проверить обязательные/рекомендуемые инструменты;
- зарегистрировать MCP-сервер Binnacle в конфиге каждого найденного harness;
- настроить telemetry там, где это поддерживается;
- сообщить, сколько истории сессий harness найдено и как далеко в прошлое она уходит, затем спросить, сколько импортировать: число дней, по умолчанию 90, или всё;
- создать минимальные hooks/шаблоны проектной документации;
- никогда не перезаписывать существующий файл и дополнять его только разделом, показанным в плане, который она один раз просит подтвердить (ADR-0034).

Что входит в план, пункт за пунктом, описано в [Существующем проекте](02-existing-project-adopt.ru.md#что-делают-binn-audit-и-binn-init), *Что делают `binn audit` и `binn init`*.

#### Из чата

Настройка работает и из чата, и из терминала. В Claude Code `/binnacle:init [path]` запускает `binn init --plan --json`, показывает в чате тот же план, каждый пункт целиком, вместе с историей сессий и окном импорта, которое он использует, и спрашивает один раз; назовите там другое окно, чтобы увидеть план с ним. Записывает его только ваше «да» в чате, через `binn init --apply <id>`, который отказывается от плана, изменившегося с момента показа, и тогда навык показывает новый план и спрашивает снова (ADR-0037). Навыку не нужен демон, и он никогда не коммитит: просмотрите и закоммитьте то, что записал init, сами, как после запуска в терминале. При остановленном демоне регистрация в план не входит, и `/binnacle:daemon start`, а затем `/binnacle:register` её добавляют. Об автозапуске в чате ничего не спрашивается, поэтому план его не включает: вместо этого его заметки называют `binn daemon autostart on`. Когда init записывает `.mcp.json`, навык в конце говорит открыть новую сессию в репозитории и одобрить сервер `binnacle` проекта: Claude Code читает `.mcp.json` только при старте сессии. Навык доступен, когда плагин `binnacle` установлен, а это делает на уровне пользователя первый `binn init` на этой машине.

### 3. От видения к roadmap

Запустите `/binnacle:roadmap` (`binnacle-roadmap` в другом harness). Он читает `<knowledge.docs>/vision.md`; если его нет, спрашивает, что это за проект, для кого он и что в него не входит, по одному вопросу, и по «да» владельца записывает видение его словами. Затем он предлагает эпики в порядке зависимостей, у каждого строка объёма, и по «да» владельца записывает строки roadmap, его раздел `## Epics` и Next action, которое грилит первый эпик, и коммитит только эти файлы, никогда не пушит. Демон ему не нужен. При повторном запуске он предлагает дополнения и перестановки среди не начатых эпиков и никогда не трогает эпик `done` или строку со ссылкой на спеку.

### 4. Старт Product

Откройте свежий чат поддерживаемого coding agent и вызовите логический `/product`, затем `/daily` или текущее действие планирования. В Claude Code это `/binnacle:product` и `/binnacle:daily`. Next action, записанное навыком roadmap, грилит первый эпик.

### 5. Каждый эпик

`binn init` уже записал соглашения, которые записал бы upstream-навык настройки, поэтому каждый эпик из roadmap идёт по потоку проектирования, начиная с Next action:

```text
grill-with-docs
        ↓
to-spec
        ↓
to-tickets
```

Затем каждый тикет выполняется в отдельной сессии командой `/binnacle:task run <ticket>`. Не заставляйте `binn init` втайне выполнять интерактивный поток grill/spec.

### Инструменты workflow

`binn init` устанавливает или проверяет рекомендуемый профиль Standard:

- Matt Pocock Skills;
- Ponytail;
- Serena;
- Graphify;
- Context7;
- ast-grep;
- опциональная интеграция с Obsidian.

## Философия установки

`binn init` должен различать:

- **required** — собственные части Binnacle;
- **recommended** — инструменты контекста/workflow;
- **optional** — Obsidian или дополнительные возможности Graphify.

Если сторонний инструмент уже есть и настроен, не переустанавливайте его вслепую.
